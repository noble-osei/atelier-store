# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Next.js 16 (App Router, `src/` dir, Cache Components) · React 19 · TypeScript (strict) · Tailwind CSS v4 · Better Auth · Drizzle ORM · Neon Postgres. The storefront has a home page and product pages; the product catalog lives in Postgres.

## Commands

Use **pnpm only**: never `npm`, `npx` or `yarn`. Run one-off CLIs with `pnpm dlx`, add packages with `pnpm add` (`-D` for dev). The lockfile is `pnpm-lock.yaml`; never create a `package-lock.json`.

```bash
pnpm install         # install dependencies
pnpm dev             # Next.js dev server (Turbopack)
pnpm build           # production build
pnpm lint            # ESLint (flat config, next core-web-vitals + typescript)
pnpm typecheck       # `next typegen` then `tsc --noEmit`
pnpm db:generate     # SQL migrations into drizzle/ from src/db/schema.ts
pnpm db:migrate      # apply migrations to Neon
pnpm db:push         # push schema directly (prototyping only)
pnpm db:studio       # Drizzle Studio
pnpm db:seed         # wipe and reload the catalog from src/db/seed-data.ts (dev only)
pnpm auth:generate   # generate Better Auth tables into src/db/auth-schema.ts
```

No test framework is set up yet, so there is no test command.

## Environment

Copy `.env.example` to `.env.local`. `DATABASE_URL` (Neon pooled connection string) is required for `dev` and `build`: `src/db/index.ts` throws at import time if it is missing. Better Auth also needs `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`. `drizzle.config.ts` loads env files with `@next/env`, so Drizzle Kit reads the same `.env.local` as Next.

## Architecture

- **Database**: `src/db/index.ts` exports a single `db` built with the Neon HTTP driver (`drizzle-orm/neon-http`), typed with everything exported from `src/db/schema.ts`. `schema.ts` is the single entry point for tables: Drizzle Kit, the `db` client, and the Better Auth adapter all read it, so new table files must be re-exported from there.
- **Auth**: `src/lib/auth.ts` is the Better Auth server instance using the Drizzle adapter (`provider: "pg"`, same schema). No auth methods (email/password, social) are configured yet. The `nextCookies()` plugin must stay **last** in `plugins` so Server Actions can set cookies. All auth HTTP traffic goes through the catch-all `src/app/api/auth/[...all]/route.ts`. `src/lib/auth-client.ts` is the React client (same-origin by default).
- **Server-only boundary**: `src/db/index.ts` and `src/lib/auth.ts` import `server-only`; never import them from Client Components. Use `authClient` on the client.
- **Next config**: `cacheComponents` and `partialPrefetching` are enabled in `next.config.ts`, so data fetching follows the Cache Components model (`"use cache"`, Suspense boundaries for dynamic data). Tailwind v4 runs through the `@tailwindcss/turbopack` loader.
- **Design system**: everything lives in `src/app/globals.css`. Raw tokens (`--ink`, `--canvas`, `--gutter`, ...) are on `:root`; static theme values sit in `@theme static`; tokens pointing at runtime vars sit in `@theme inline` so the `theme-inverse` scope can flip them. Tailwind's default color palette, radii and shadows are reset: use the semantic tokens and the `btn`, `link`, `input`, `container-*`, `grid-products`, `media-*` and `type-*` primitives.
- **Typed routes**: layouts/pages use the global `LayoutProps<"/">` / `PageProps` helpers generated by `next typegen` (that is why `typecheck` runs typegen first).
- Path alias: `@/*` → `src/*`.

## Database conventions

- **Tables**: catalog tables live in `src/db/catalog-schema.ts` (`categories`, `products`, `product_stock`). Put new domains in their own `*-schema.ts` file, re-exported from `schema.ts`.
- **Columns**: give every column an explicit snake_case name (`integer("category_id")`); there is no `casing` config. Primary keys are `integer` identity columns. Timestamps are `timestamptz` (`created_at`, `updated_at`).
- **Money**: integer cents (`price_cents`), never floats or numeric. Convert to dollars only in the row mapper.
- **Stock**: one `product_stock` row per product and size (`"One size"` for single-size items), with `position` for display order. It is stock only, not a variant system: no per-size SKU, price or image.
- **Lists read with their parent** (images, details, colors) are typed `jsonb` (`.$type<T[]>()`), not child tables.
- **Foreign keys**: `restrict` for lookups (product → category), `cascade` for owned rows (stock → product). Enforce invariants with `check` constraints (price > 0, quantity >= 0).
- **Imports in schema files are relative** (`../lib/images`): Drizzle Kit does not resolve the `@/` alias.
- **Reads**: pages never query `db` directly. They call server-only getters (`src/lib/product-queries.ts`) that use `"use cache"` + `cacheTag("products")` and map rows to the domain types in `src/lib/products.ts`. That types file must not import the database, because Client Components import it. After any write that changes products or stock, call `revalidateTag("products")`.
- **Migrations**: change the schema, run `pnpm db:generate`, review the SQL in `drizzle/`, then `pnpm db:migrate`. Never edit a migration that has been applied. `db:push` is for throwaway prototyping only.
- **Scripts outside Next** (seed, one-off tools) build their own Neon client: `src/db/index.ts` imports `server-only`, which throws outside Next. They run with `tsx` and load env with `@next/env`.
- **Scope**: the schema covers products, categories and stock only. Do not add carts, orders, payments, reviews, wishlists or variants unless asked.

## Adding the Better Auth tables

1. `pnpm auth:generate` (uses the `auth` CLI package via `pnpm dlx`, pinned to the same version as `better-auth`; `@better-auth/cli` is deprecated and stopped at 1.4.x)
2. Uncomment `export * from "./auth-schema";` in `src/db/schema.ts`
3. `pnpm db:generate && pnpm db:migrate`
